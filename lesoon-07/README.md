# שיעור 7 · טיפול בשגיאות: Retry ו-Error Workflow

## מטרה

כשזרימת הסיווג נכשלת, השגיאה לא נעלמת. היא נרשמת בטאב "שגיאות" בגיליון, עם השעה, הזרימה, הצומת, ההודעה וקישור להרצה.

## כלים

‏n8n Cloud, ‏Gemini API דרך HTTP Request, ו-Google Sheets ליומן השגיאות.

## הזרימות

הזרימה הראשית היא עותק של זרימת שיעור 6, עם ניסיון חוזר בקריאה ל-Gemini ועם Error workflow מוגדר ב-Settings:

```
Webhook (GET, path: classify7)
  → HTTP Request (Gemini, POST, Retry On Fail: 3 ניסיונות, 2000ms)
  → Edit Fields
  → Google Sheets (טאב "פניות נכנסות")
  → Respond to Webhook

Settings → Error workflow: זרימת השגיאות
```

זרימת השגיאות רצה אוטומטית כשהזרימה הראשית נכשלת:

```
Error Trigger
  → Google Sheets (טאב "שגיאות")
```

## נתוני בדיקה

שלוש קריאות ל-Production URL, לפי הסדר. קריאה 1 מוודאת שהכול עובד, קריאה 2 נכשלת בכוונה, וקריאה 3 מוודאת שהתיקון החזיר את המצב לקדמותו.

| # | מצב המפתח | פנייה | תוצאה צפויה |
|---|---|---|---|
| 1 | תקין | ההזמנה שלי לא הגיעה כבר שבועיים | משלוח, רגילה. אין שורה בטאב שגיאות |
| 2 | שבור | רציתי להחליף את הכיסא שקיבלתי בצבע אחר | הודעת שגיאה. שורה אחת בטאב שגיאות |
| 3 | תקין | רציתי להחליף את הכיסא שקיבלתי בצבע אחר | החזרה, רגילה. אין שורה נוספת בטאב שגיאות |

המפתח השבור הוא Credential נפרד עם ערך שגוי בכוונה, כדי שלא לגעת במפתח האמיתי.

## מה נבדק

| # | בדפדפן | שורה בשגיאות | שורה בפניות נכנסות | תואם |
|---|---|---|---|---|
| 1 | משלוח, רגילה | לא | כן | ✓ |
| 2 | הודעת שגיאה | כן, 5 מתוך 5 עמודות | לא | ✓ |
| 3 | החזרה, רגילה | לא | כן | ✓ |

בשורת השגיאה של קריאה 2 נרשמו הזרימה, הצומת (HTTP Request), ההודעה מ-Gemini (Bad request - please check your parameters) וקישור להרצה שנכשלה.

## תוצאה נמדדת

3 מתוך 3 קריאות התנהגו כצפוי. השגיאה של קריאה 2 נרשמה ביומן השגיאות עם 5 מתוך 5 עמודות, וזו השורה היחידה שנוספה שם.

## מה למדתי

- ‏**Retry ו-Error Workflow עושים דברים שונים.** ‏Retry מוגדר בכל צומת בנפרד, ופותר תקלה זמנית כמו 503. ‏Error Workflow רץ רק אחרי שכל הניסיונות נכשלו. במפתח שגוי Retry לא עוזר, רק מעכב.
- ‏**Error Trigger רץ רק בהרצת production.** כשמריצים ידנית בעורך את הזרימה הראשית, היא לא מפעילה אותו. כשמריצים ידנית את זרימת השגיאות עצמה, ‏n8n כותב שורת דוגמה (Example Workflow) ולא שגיאה אמיתית.
- **זרימת שגיאות חייבת להיות Published.** בלי פרסום, היא מופיעה באפור ברשימת Error workflow ולא ניתנת לבחירה.
- **שינוי בזרימה שפורסמה נכנס לתוקף רק אחרי פרסום מחדש.** תיקון במיפוי העמודות לא השפיע על ההרצה עד שלחצתי Publish שוב.
- **ב-Header Auth יש שני "שמות".** שם ה-Credential הוא תווית שמופיעה בכותרת החלון. השדה Name הוא שם ה-Header שנשלח ל-API (`x-goog-api-key`).

## מגבלות

הבדיקה כיסתה שגיאה קבועה אחת, מפתח שגוי. את פעולת ה-Retry בתקלה זמנית אי אפשר היה לבדוק, כי אין דרך לייצר 503 מ-Gemini לפי דרישה.

לפני ההעלאה נבדק ששני קובצי הזרימות לא כוללים את מפתח ה-API. הכתובת הציבורית בוטלה בסיום, וה-Credential השבור נמחק.
