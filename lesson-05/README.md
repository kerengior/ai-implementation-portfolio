# שיעור 5 · קריאה ישירה ל-API של מודל
 
## מטרה
 
לשלוח את 10 פניות הלקוחות משיעור 1 למודל Gemini מתוך n8n, דרך צומת HTTP Request ולא דרך צומת מובנה, ולקבל לכל פנייה פלט JSON מובנה עם קטגוריה, דחיפות ונימוק.
 
## מה נבנה
 
זרימה ב-n8n:
 
1. **Get row(s) in sheet** קורא את 10 הפניות מהגיליון.
2. **HTTP Request** שולח בקשת POST ל-Gemini API, פנייה אחת בכל קריאה.
3. **Edit Fields** מפרק את תשובת המודל (טקסט בפורמט JSON) לשדות נפרדים.
4. הפלט נכתב לטאב "פלט שיעור 5".
פרטי הבקשה:
 
- **Method:** POST
- **אימות:** מפתח API ב-header בשם `x-goog-api-key`, שמור ב-Credential של n8n ולא בקוד.
- **גוף הבקשה:** כללי הסיווג ב-`systemInstruction`, טקסט הפנייה ב-`contents`, וסכמת JSON עם enum ב-`generationConfig`.
## תוצאה
 
| מדד | תוצאה |
|:---|:---|
| קטגוריה נכונה | 10 מתוך 10 |
| דחיפות נכונה | 10 מתוך 10 |
| JSON תקין | 10 מתוך 10 |
 
התוצאה זהה לשיעור 1 (Google AI Studio), הפעם בתוך זרימה אוטומטית.
 
## מה למדתי
 
- **GET מול POST:** בשיעור 4 ביקשתי מידע (GET). כאן שלחתי מידע וקיבלתי עליו תשובה (POST).
- **מפתח API לא נכנס לקוד.** הוא נשמר ב-Credential, והקובץ המיוצא מכיל רק את שם ה-Credential.
- **`JSON.stringify` לטקסט חופשי.** פנייה עם גרשיים (למשל ש"ח) שוברת את גוף הבקשה. העטיפה ב-`JSON.stringify` מסמנת את התווים הבעייתיים.
- **תקלה ותיקון:** הבקשה הראשונה נכשלה עם `Invalid value at 'generation_config.response_format...'`. המבנה `responseFormat` לא נתמך. התיקון: `responseMimeType` ו-`responseSchema` ישירות תחת `generationConfig`.
- **התשובה היא טקסט, לא שדות.** המודל מחזיר מחרוזת שנראית כמו JSON, וצריך לפרק אותה בצעד נפרד.
- **למה HTTP ולא צומת Gemini מובנה:** לא לכל מערכת יש צומת, הבקשה הגולמית קלה יותר לדיבאג, ויש שליטה מלאה בכל שדה.
