# שיעור 6 · Webhook: סיווג פנייה שמגיעה מבחוץ
 
## מטרה
 
להפעיל את זרימת הסיווג משיעור 5 מבחוץ: מערכת אחרת שולחת פנייה לכתובת של n8n, הזרימה מסווגת אותה ב-Gemini, ומחזירה את הסיווג למי שפנה.
 
## כלים
 
n8n Cloud, ‏Gemini API עם פלט JSON לפי סכמה, ו-Google Sheets לרישום הפניות.
 
## הזרימה
 
```
Webhook (GET, path: classify)
  → HTTP Request (Gemini, POST)
  → Edit Fields (קטגוריה, דחיפות, נימוק, פנייה)
  → Google Sheets (טאב "פניות נכנסות")
  → Respond to Webhook (מחזיר את הסיווג לדפדפן)
```
 
קובץ הזרימה: [lesson-06-webhook-classification.json](lesson-06-webhook-classification.json)
 
## נתוני בדיקה
 
שלוש פניות חדשות, שלא היו בסט של שיעור 1. כל פנייה בודקת כלל אחר מכללי הסיווג.
 
| # | פנייה | קטגוריה צפויה | דחיפות צפויה | הכלל שנבדק |
|---|---|---|---|---|
| 1 | חויבתי פעמיים על אותה הזמנה בכרטיס האשראי | תשלום | גבוהה | חיוב כפול |
| 2 | המטען שקיבלתי מתחמם מאוד ומריח שרוף | תקלה במוצר | גבוהה | מוצר מסוכן (חום) |
| 3 | האם אתם שולחים גם לאילת? | שאלה מקדימה | נמוכה | שאלה של מי שעוד לא הזמין, גם אם היא על משלוח |
 
## מה נבדק
 
| # | קטגוריה שהתקבלה | דחיפות שהתקבלה | תואם |
|---|---|---|---|
| 1 | תשלום | גבוהה | ✓ |
| 2 | תקלה במוצר | גבוהה | ✓ |
| 3 | שאלה מקדימה | נמוכה | ✓ |
 
הנימוק בכל התשובות היה משפט אחד, עד 10 מילים.
 
בנוסף, משימה בלי מדריך: כל פנייה נרשמת גם בטאב "פניות נכנסות" בגיליון, עם 4 עמודות: הפנייה, קטגוריה, דחיפות ונימוק. הדפדפן ממשיך לקבל את התשובה.
 
## תוצאה נמדדת
 
3 מתוך 3 פניות חזרו לדפדפן עם הקטגוריה והדחיפות הצפויות. כל פנייה נרשמה כשורה אחת בטאב, ו-4 העמודות מלאות.
 
## מה למדתי
 
- ‏Webhook הוא ההפך מ-HTTP Request. ב-HTTP Request ‏n8n פונה החוצה, וב-Webhook מערכת אחרת פונה אל n8n ומפעילה את הזרימה.
- ‏Test URL עובדת רק אחרי לחיצה על Execute workflow, לקריאה אחת, והנתונים מוצגים בעורך. ‏Production URL עובדת כל הזמן אחרי פרסום, וההרצות מופיעות בלשונית Executions.
- הביטוי `$json` מחזיר רק את הנתונים מהצומת הקודם. כדי להגיע לנתונים מצומת מוקדם יותר, פונים אליו בשם: `$('Webhook').item.json.query.text`.
- את טקסט הפנייה לוקחים מהמקור ולא מבקשים מהמודל להחזיר אותו. מודל לא מעתיק טקסט באופן מובטח, ועלול לתקן או לקצר.
- ‏GET מבקשת מידע מהשרת, והפרמטרים נכנסים לכתובת. ‏POST שולחת תוכן לשרת בגוף הבקשה. כאן הקריאה מהדפדפן היא GET, והקריאה ל-Gemini היא POST.
## מגבלות
 
הבדיקה נעשתה מסרגל הכתובות של הדפדפן, ולכן ב-GET, עם הפנייה בכתובת. במערכת אמיתית שולחת פניות הקריאה תהיה POST, עם הטקסט בגוף הבקשה. בגלל זה צריך לשנות את ה-Method של ה-Webhook, ואת הביטוי ל-`$json.body.text`.
 
הכתובת הציבורית בוטלה בסיום, כי כתובת פתוחה לכל אחד מפעילה את מפתח Gemini שבתשלום.
