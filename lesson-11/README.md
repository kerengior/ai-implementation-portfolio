# שיעור 11 · זיכרון שיחה

פרויקט B · עוזר מטלות הבית · שיעור 3 מתוך 5

## מה נבנה

לסוכן המטלות משיעור 10 נוסף צומת **Simple Memory**. ה-Session Key מגיע מטריגר הצ׳אט, ו-Context Window Length הוא 5. המודל עצמו לא זוכר כלום בין הודעות. n8n שומר את היסטוריית השיחה, ושולח אותה למודל מחדש עם כל הודעה.

## איך נבדק

אותו תסריט של 3 תורות הורץ פעמיים, פעם בלי זיכרון ופעם איתו. אחר כך נבדקה שיחה חדשה.

1. אני נועה, מה נשאר לי לעשות?
2. ומה עם איתי?
3. סיימתי את הראשונה שלי

## תוצאה

**שאלת ההמשך נענתה נכון רק עם זיכרון. 7 מתוך 7 תורות התנהגו כצפוי.**

| תור | בלי זיכרון | עם זיכרון |
|---|---|---|
| 1 | 2 המטלות של נועה | 2 המטלות של נועה |
| 2 | כל 5 המטלות של איתי (פירוש כללי) | רק המטלה שנשארה לאיתי (המשך של "מה נשאר") |
| 3 | שאל מי כותב ואיזו מטלה. לא סימן כלום | סימן את מטלה 10 של נועה, ולא את מטלה 14 של איתי |
| שיחה חדשה | | לא זכר את השיחה הקודמת |

## ממצאים

1. **תשובה סבירה לא מוכיחה שהמודל הבין את ההקשר.** בלי זיכרון, "ומה עם איתי?" קיבלה תשובה הגיונית, כי המודל ניחש פירוש. את "שלי" בתור 3 אי אפשר לנחש, ולכן רק התור הזה בודק באמת את הזיכרון.
2. **בלוג רואים מה הזיכרון עושה.** בלי זיכרון, ה-Input של Gemini כולל רק את ה-System Message ואת ההודעה האחרונה. עם זיכרון, ההודעות הקודמות מופיעות לפני ההודעה החדשה.
3. **הזיכרון רץ בכל סבב של המודל.** בתור שבו הסוכן קרא מהגיליון, כתב אליו וענה, Gemini וה-Memory הופעלו 3 פעמים כל אחד.
4. **ה-Session Key מפריד בין שיחות.** אם המפתח קבוע, כל המשתמשים חולקים זיכרון אחד, וההקשר מתערבב בין ילדים. בוואטסאפ המפתח יהיה מספר הטלפון של השולח.
5. **Simple Memory מתאים ללמידה ולא לשימוש קבוע.** הזיכרון נשמר בתוך n8n ונמחק כשהוא מופעל מחדש. למערכת בשימוש קבוע משתמשים ב-Postgres או ב-Redis.
