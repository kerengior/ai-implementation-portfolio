# שיעור 15 · Embeddings ו-Vector Store ב-n8n

פרויקט C · שאלות על מסמכי בניית הבית · שיעור 2 מתוך 3

## מה נבנה

זרימת RAG אחת ב-n8n עם שתי שורות:

| שורה | מתי רצה | צמתים |
| --- | --- | --- |
| הכנה | פעם אחת, ידנית | Google Drive (חיפוש בתיקייה) ← Download ← Extract from File (PDF) ← Simple Vector Store (Insert) עם Embeddings Gemini ו-Default Data Loader |
| שאלה | בכל הודעה בצ׳אט | Chat Trigger ← AI Agent (Gemini) ← כלי house_docs: Simple Vector Store (Retrieve), Limit 4, עם metadata של שם הקובץ |

אותם 3 מסמכים ואותן 10 שאלות כמו ב[שיעור 14](../lesson-14/), כדי להשוות.

## תוצאות (n8n)

| מדד | תוצאה |
| --- | --- |
| תשובה נכונה | 10/10 |
| מקור נכון (הקטע הנכון בין 4 הקטעים שנשלפו) | 10/10 |
| תשובה מלאה (כל הפרטים מהתשובה הצפויה) | 8/10 |
| שאלה עמומה (שני מסמכים) | שתי התשובות הופיעו |
| שאלה מחוץ למסמכים | לא המציא |
| שאלה בניסוח שונה ("משלוח" במקום "הובלה") | נמצאה לפי משמעות |

## ממצאים

1. **PDF סרוק.** אחד המסמכים היה סריקה בלי שכבת טקסט, והחילוץ החזיר טקסט ריק. הוא עבר OCR דרך Google Docs, והטקסט שיצא היה בלי רווחים בין המילים.
2. **Data Loader שטוען הכול.** בהגדרת ברירת המחדל כל שדה JSON (מזהה, שם קובץ, גרסה, תאריכים) נכנס למאגר כקטע נפרד: 38 קטעים במקום 5. תוקן כך שרק שדה הטקסט נטען.
3. **טקסט בלי רווחים מדורג נמוך.** בשאלת ההובלה, המסמך עם הטקסט הצמוד דורג אחרון מתוך 4. אילו ה-Limit היה 3, הוא לא היה נשלף, והתשובה הייתה חלקית בלי שום סימן לכך.
4. **מאגר קטן מדי למבחן אחזור.** 5 קטעים מול Limit 4: האחזור כמעט לא בוחר. נבדק ב[שיעור 16](../lesson-16/).
5. **העברית ישרה.** חילוץ הטקסט של n8n קרא את העברית נכון, בניגוד לתצוגת הטקסט של דרייב.

## מה למדתי

- קודם בודקים את הטקסט שחולץ, ורק אחר כך מכניסים למאגר. רוב התקלות היו לפני ה-embeddings.
- ה-Logs מראים אילו קטעים נשלפו, וכך אפשר להבחין בין כשל אחזור לכשל של המודל.
- Simple Vector Store שומר בזיכרון בלבד. מתאים לפיתוח, לא לייצור.
