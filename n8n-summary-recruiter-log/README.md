# משימת סיכום n8n · יומן מגייסים ומעקב הגשות

## הבעיה

בחיפוש עבודה שולחים גרסה אחרת של קורות החיים לכל משרה, ואחרי כמה שבועות כבר לא זוכרים מה נשלח לאן. כשמגייס מתקשר, צריך לדעת מיד על איזו משרה מדובר ומה קרה עד עכשיו. ואחרי כל שיחה צריך צעד הבא, שלא יישכח.

## מה נבנה

סוכן צ׳אט אחד שמטפל גם בהגשות וגם בשיחות, עם שתי תת-זרימות:

```
צ׳אט (עם קבצים) ──► IF: הגיע קובץ? ──כן──► Google Drive Upload (שם זמני)
                                   └─לא──────────────┐
                                                     ▼
                                          AI Agent (Gemini) + זיכרון שיחה
   כלים:
   fetch_job_page ············ קריאת דף המשרה (HTTP)
   get_next_submission_id ···· תת-זרימה: מזהה הגשה הבא (Sheets + Code)
   save_job_row ·············· Append or Update לפי submission_id
   rename_cv_file ············ שם קבוע לקובץ: cv-<id>-<company>.pdf
   log_call ·················· תת-זרימה: רישום שיחה
   log_call_for_submission ··· אותה תת-זרימה, אחרי שהמשתמשת בחרה הגשה

תת-זרימה log_call:
מציאת ההגשה לפי חברה ──► (כמה התאמות? מחזירה multiple, והסוכן שואל)
  ──► Gemini: סיכום, שלב, צעד הבא, תאריך תזכורת (פלט מובנה)
  ──► אירוע ביומן (לא בדחייה) ──► שורה בטאב calls ──► עדכון סטטוס בטאב jobs
```

**הגיליון:** טאב `jobs` (שורה לכל הגשה) וטאב `calls` (שורה לכל שיחה). מזהה ההגשה מקשר ביניהם.

**מזהה הגשה:** 8 ספרות, `ddmmyy` ועוד מספר רץ של שתי ספרות. המזהה מחושב בקוד מתוך הגיליון, לא על ידי המודל.

## תוצאות

נתוני הבדיקה: 3 הגשות למשרות ו-4 שיחות (שמות החברות כאן בדויים).

| בדיקה | תוצאה |
| --- | --- |
| הגשות: שורה עם מזהה, קובץ בשם הנכון וקישור שנפתח | 3/3 |
| שיחה 1, אלפא: "ראיון ביום חמישי הבא ב-10:00" | שלב ראיון, אירוע בתאריך ובשעה הנכונים ✓ |
| שיחה 2, אלפא שוב: "מבחן בית עד סוף השבוע" | שורה שנייה עם אותו מזהה, הסטטוס התעדכן, בלי הגשה כפולה ✓ |
| שיחה 3, בטא: "לא ממשיכים כרגע" | שלב דחייה, בלי אירוע ביומן ✓ |
| שיחה 4, חברת השמה שלא הגשתי אליה | "לא מקושר", אף הגשה לא השתנתה, תזכורת ליום שנאמר ✓ |
| קישור לדף המשרה חסום | הסוכן שאל על הפרטים ולא המציא ✓ |
| Error Workflow מחובר | 3/3 זרימות |

## החלטות

| החלטה | למה |
| --- | --- |
| העלאת הקובץ לפני הסוכן, לא ככלי שלו | כלי של סוכן מקבל רק ערכי טקסט מהמודל, לא קובץ. ההעלאה גם לא דורשת שיקול דעת. |
| המזהה מחושב בתת-זרימה | המודל לא יודע אילו מזהים כבר קיימים ולא יכול להבטיח מזהה ייחודי. |
| `save_job_row` אחד (Append or Update) במקום שמירה ועדכון נפרדים | מחוסר זמן. החיסרון: בעדכון המודל צריך לשלוח שוב את כל השדות, וטעות במזהה יוצרת שורה חדשה בשקט. |
| `log_call` נבנתה ב-AI Workflow Builder של n8n | תרגול של בדיקת זרימה שמודל בנה. נבדקה צומת אחר צומת, ותוקנו בה שתי נקודות. |
| שני כלים לאותה תת-זרימה | המודל לא שלח שדה אופציונלי, וכך בכל כלי כל השדות נדרשים. |
| דחייה בלי תזכורת | אין צעד הבא. התאריך שנאמר בשיחה נשמר בגיליון. |
| חיפוש ההגשה לפי חברה, ושאלה כשיש כמה | פשוט, אבל לא מזהה טעויות כתיב (ראו "מה הייתי משנה"). |

## ממצאים

1. **כלי של סוכן לא מקבל קובץ (binary).** לכן ההעלאה עברה לצומת שלפני הסוכן, והסוכן מקבל רק את מזהה הקובץ.
2. **עמודה שלא סומנה כ-"Defined by agent" נכתבת ריקה, והכלי מחזיר הצלחה.** הסוכן כתב "תויק" בכנות. הצלחה של כלי לא אומרת שהנתונים נכונים.
3. **"בהודעה" בפרומפט פורש כ"בהודעה הנוכחית".** הקובץ הגיע בהודעה הראשונה, והסוכן סימן אותו כחסר בהודעה השנייה. תוקן: "באחת ההודעות בשיחה".
4. **Append יצר שורה כפולה כשאותה הגשה נשמרה פעמיים.** Append or Update לפי המזהה פתר.
5. **המודל קבע תאריכים בפורמט קצר, ובפעם אחת תאריך שגוי.** תאריך שהקוד יודע לחשב לא צריך להגיע מהמודל.
6. **אתר המשרות חסום על ידי Cloudflare** (403 עם דף "Just a moment"). הגיבוי של שאלת פרטים בצ׳אט עבד.
7. **Gemini לא שלח שדה אופציונלי, גם כשהתבקש לשלוח ערך ריק או "none".** פוצל לשני כלים, וכל השדות בהם נדרשים.
8. **`caller` הוא שם שמור ב-JavaScript ונדחה כמפתח של `$fromAI`** ("Invalid parameter key"). השגיאה הזו הוסתרה מאחורי שגיאה אחרת, ונחשפה רק כשהראשונה תוקנה.
9. **התת-זרימה לא בודקת את הקלט:** בניסיון שנכשל נרשמה שיחה ריקה.

## מה הייתי משנה

- **בדיקת קלט בכניסה ל-`log_call`:** לא לרשום שיחה בלי חברה והערות.
- **התאמת חברה גמישה:** טבלת שמות חלופיים (Wix / וויקס), ושאלת אישור כשאין התאמה מדויקת, במקום "לא מקושר" בשקט.
- **להשתמש בתפקיד:** אם בהערות מופיע תפקיד שתואם לאחת ההגשות, לבחור אותה בלי לשאול.
- **שני כלים נפרדים לשמירה ולעדכון,** כדי שעדכון לא יוכל למחוק שדות או ליצור שורה כפולה.
- **תאריכים מהקוד ולא מהמודל.**
- **קובץ שמגיע בשיחה חדשה:** לחפש בגיליון הגשה עם `cv_status = חסר`, במקום להסתמך על זיכרון השיחה.
- **פורמט המזהה `yymmdd`,** כדי שהגיליון ימוין לפי תאריך.

## בארגון אמיתי

- **פרטיות:** קובצי קורות חיים ושמות מגייסים הם מידע אישי. הגיליון, תיקיית הדרייב והיומן פרטיים, ובריפו הזה אין אף אחד מהם.
- **קריאת אתרי משרות לא אמינה.** רוב האתרים חוסמים קריאה אוטומטית. עדיף API רשמי, או שהמשתמש מדביק את תיאור המשרה.
- **הצ׳אט לא פורסם בקישור ציבורי.** בשימוש אמיתי נדרשת הזדהות (Basic Auth לפחות), כי כל מי שיש לו גישה יכול לכתוב לגיליון ולדרייב.
