# פרויקט A · מיון פניות שירות לקוחות

## הבעיה

חנות מקוונת לכלי בית מקבלת פניות מלקוחות: משלוחים, החזרות, חיובים ותקלות. נציג צריך לקרוא כל פנייה, להחליט לאיזה צוות היא שייכת ומה הדחיפות שלה, ולנסח תשובה ראשונית. פניות דחופות, כמו חיוב כפול או מוצר מסוכן, יכולות לחכות בתור מאחורי שאלות פשוטות.

## הפתרון

זרימה ב-n8n שקוראת פניות מגיליון, שולחת כל פנייה ל-Gemini, ומחזירה לכל פנייה:

- **קטגוריה** · אחת מחמש: משלוח, החזרה, תשלום, תקלה במוצר, שאלה מקדימה
- **דחיפות** · גבוהה, רגילה או נמוכה
- **נימוק** · משפט אחד
- **טיוטת מענה** · 2–3 משפטים, לפי כללים שמונעים הבטחות שאי אפשר לעמוד בהן

```
Google Sheets ──► HTTP Request (Gemini) ──► Edit Fields ──► Google Sheets
  קריאת פניות      סיווג + טיוטה, פלט JSON      פירוק התשובה      כתיבת התוצאה
                   Retry ×3
                       │ כשל סופי
                       ▼
                 Error Workflow ──► טאב שגיאות (שעה, צומת, סיבה)
```

**החלטות עיקריות:**

- **פלט מובנה עם סכמה ו-enum:** המודל לא יכול להחזיר קטגוריה שלא קיימת, והפלט תמיד JSON תקין.
- **קריאה ישירה ל-API דרך HTTP Request,** ולא צומת מובנה: שליטה מלאה בגוף הבקשה ובמבנה הפלט.
- **מפתח ה-API שמור ב-Credential של n8n:** הוא לא נכנס לקבצים שמיוצאים לגיטהאב.
- **שתי שכבות של טיפול בשגיאות:** Retry לתקלות זמניות, ו-Error Workflow שרושם כל כשל סופי, כך שאף פנייה לא נעלמת בלי עקבות.

## תוצאות

נבדק על סט של 30 פניות עם תוצאה צפויה, כולל מקרים גבוליים שנבחרו בכוונה (למשל שאלת תשלום לפני הזמנה, או מוצר שהגיע פגום מול החזרת מוצר תקין).

| מדד | תוצאה |
|---|---|
| דיוק קטגוריה | 30/30 (100%) |
| דיוק דחיפות | 30/30 (100%) |
| טיוטות תקינות לפי מחוון של 4 כללים | 30/30 (100%) |
| זמן ריצה ל-30 פניות | 19.58 שניות |
| כשל מכוון (מפתח שבור) | נרשם בטאב שגיאות עם השעה והסיבה |

## מה הייתי משנה

1. **סט בדיקה קשה יותר.** 30 הפניות נכתבו בצורה נקייה. פניות אמיתיות כוללות שגיאות כתיב, כמה בעיות בפנייה אחת, אנגלית ופניות ריקות. 100% על הסט הזה לא מבטיח 100% בייצור.
2. **צורת פנייה אחידה בטיוטות.** המודל עבר בין יחיד לרבים, וניחש מגדר לפי ניסוח הפנייה. הכללים צריכים לקבוע צורה אחת.
3. **פחות ניסוחים גנריים.** "בהקדם" חוזר כמעט בכל טיוטה.
4. **בדיקת טיוטות שמתאימה להיקף.** בדיקה ידנית לפי מחוון עובדת ל-30 פניות, לא ל-3,000. בהיקף גדול: בדיקות אוטומטיות (ספירת משפטים, מילים אסורות), מודל שבודק את הטיוטות מול המחוון, ודגימה ידנית.
5. **המחוון בודק רק מה אסור.** הוא לא בודק אם הטיוטה באמת עוזרת ללקוח.
