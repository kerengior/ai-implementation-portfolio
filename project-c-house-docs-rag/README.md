# פרויקט C · שאלות על מסמכי בניית הבית (RAG)

## הבעיה

בפרויקט בנייה מצטברות הצעות מחיר בקובצי PDF, לפעמים משני ספקים לאותו מוצר. כדי לענות על שאלה פשוטה, כמו כמה עולה ההובלה או מה תנאי התשלום, צריך לפתוח כל קובץ ולחפש בו. התשובה צריכה להגיע מהמסמכים עצמם, עם מקור שאפשר לבדוק.

## מה נבנה

**NotebookLM כנקודת ייחוס**, ולצידו **זרימת RAG ב-n8n** עם ציטוט מקור:

```
הכנה (פעם אחת):
Google Drive ──► Extract from File ──► Embeddings Gemini ──► Simple Vector Store

שאלה (בכל הודעה):
צ׳אט ──► AI Agent (Gemini) ──► house_docs: אחזור Limit 2 ──► תשובה + מקור + ציטוט
```

הנתונים: 3 הצעות מחיר בעברית (פרגולות, ושתי הצעות לספי חלון משני ספקים) ו-10 שאלות עם תשובה ידועה: 6 עובדות בודדות, 1 עמומה, 2 השוואות ו-1 מחוץ למסמכים. **המסמכים לא מתפרסמים.**

## תוצאות

| מדד | NotebookLM | n8n |
| --- | --- | --- |
| תשובה נכונה | 10/10 | 10/10 |
| מקור נכון | 10/10 | 10/10 |
| תשובה מלאה (כל הפרטים הצפויים) | 10/10 | 8/10 |
| מידע שלא מהמסמכים | 1 | 0 |
| שאלה עמומה: שתי התשובות | ✓ | ✓ (הספק השני דורג רביעי מתוך 4) |
| "משלוח" במקום "הובלה" | ✓ | ✓ |
| לא המציא (שאלה מחוץ למסמכים) | ✓ | ✓ |
| רואים את הקטעים שנשלפו | ✗ | ✓ (Logs) |
| ציטוט מקור בתשובה | הפניה מובנית | 3/3 מילוליים, 2/3 מוכיחים את התשובה |

**ניסוי Limit = 1:** בשאלת ההובלה נשלף מהספק השני רק סעיף התנאים הכלליים. הסוכן ענה "ההובלה לא כלולה", למרות שבמסמך יש שורה של 600 ש״ח. התשובה שגויה, מגיעה עם ציטוט מילולי, ואין בה סימן שחסר מידע.

**מסקנה:** ציטוט מקור לא מבטיח תשובה נכונה. את ההגדרות (Limit, חיתוך לקטעים) בודקים מול סט שאלות עם תשובות ידועות, שמתאים לנתונים ולסוג השאלות של המשתמשים. אחרת מתקבלות תשובות חלקיות או שגויות שנראות מבוססות.

## ממצאים

1. **PDF סרוק בלי שכבת טקסט.** החילוץ החזיר טקסט ריק. אחרי OCR הטקסט יצא בלי רווחים בין המילים.
2. **Data Loader שהכניס 38 קטעים במקום 5.** כל שדה JSON נטען כקטע נפרד. תוקן כך שרק שדה הטקסט נטען.
3. **טקסט בלי רווחים דורג אחרון.** עם Limit 3 הספק הזה היה נעלם מהתשובה.
4. **Limit שמשמיט ספק.** עם Limit 1 התקבלה תשובה שגויה עם ציטוט מילולי.
5. **ציטוט מילולי שלא מוכיח.** בטקסט משובש הציטוט היה רצף מספרים, והמודל הסיק בעצמו מה הם.
6. **זיכרון השיחה מזהם בדיקות.** כל שאלת בדיקה נשאלת בשיחה נקייה.

## מה הייתי עושה בייצור

- **מאגר קבוע** (Supabase, Pinecone, Qdrant או Postgres) במקום מאגר בזיכרון, שנמחק בכל הפעלה מחדש של n8n.
- **הכנסה אוטומטית:** זרימה נפרדת שרצה כשנוסף קובץ לתיקייה (Google Drive Trigger).
- **עדכון לפי source:** כשקובץ משתנה, מוחקים רק את הקטעים שלו ומכניסים אותו מחדש.
- **מודל embeddings קבוע:** החלפה שלו מחייבת להכניס מחדש את כל המסמכים.
- **בדיקת OCR לפני ההכנסה,** כי רוב התקלות קרו לפני ה-embeddings.
- **אבטחת מידע והרשאות:** לבדוק איפה המסמכים יושבים פיזית, ולוודא שעובד לא מקבל קטעים ממסמך שהוא לא רשאי לראות.
